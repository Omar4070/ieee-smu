# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Static website (Astro 7 + Tailwind CSS 4, no backend) for the IEEE IAS/IES/PES joint chapter of the SMU Student Branch, deployed to GitHub Pages. Content is edited by non-developer chapter officers, so content files and `README.md` recipes must keep working.

## Commands

```bash
npm run dev            # dev server, http://localhost:4321
npm run build          # astro check (types + content schemas) then astro build → dist/
npm run preview        # serve dist/
npm run check:links    # after a build: every internal href/src/srcset/#anchor in dist/ must exist
                       # (set BASE_PATH=/repo when the build used a base path)
node .claude/skills/design-taste-frontend/scripts/lint.mjs src          # banned design patterns in source
node .claude/skills/design-taste-frontend/scripts/inspect.mjs <url>     # real-browser design gate, 1440/768/390
bash scripts/screenshots.sh http://127.0.0.1:4321 /path/ [/path2/ …]   # full-page shots, 3 widths × light/dark → screenshots/
node scripts/slice-screenshots.mjs screenshots/<file>.png               # cut long shots into readable sheets
bash scripts/console-check.sh http://127.0.0.1:4321 /path/              # browser console errors
playwright-cli open <url> && playwright-cli run-code --filename=scripts/test-mobile-nav.js   # nav/keyboard/theme/overflow
playwright-cli open <url> && playwright-cli run-code --filename=scripts/test-a11y.js         # axe-core, both themes (loads axe from cdnjs)
```

There is no unit-test suite; the tests are the playwright-cli scripts above (run one by opening a browser on the page, then `run-code` with that file). Run the final design/a11y gates against `npm run preview` (production build), not the dev server.

On Windows Git Bash, prefix commands that pass a path-like env var with `MSYS_NO_PATHCONV=1` (e.g. `BASE_PATH=/repo npx astro build`), otherwise Bash rewrites it to `C:/Program Files/Git/repo`.

## Architecture

- **Content collections** (`src/content.config.ts`, Zod from `astro/zod`, Zod 4 so `z.url()` not `z.string().url()`): `events/*.md`, `news/*.md`, `team/*.json` (one file per committee year; the file sorting last by id is the "current" committee). Images in frontmatter use the `image()` helper with paths relative to the content file (`../../assets/...`). Schema enums (event `type`, `societies`, news `category`) are documented in README, so update both together.
- **`src/lib/utils.ts`** is the shared data layer: `getEvents()` splits upcoming/past using *build time* "today" (the deploy workflow rebuilds nightly so events roll into the archive), `getNews()`, `getTeams()`, date formatting via `Intl` in UTC, `fieldFor(society)` → colour class.
- **Base path:** the site may be served from `https://user.github.io/<repo>/`. `astro.config.mjs` reads `SITE_URL`/`BASE_PATH` (set by the workflow from `actions/configure-pages`). Every internal link in `.astro` files must go through `url('/path/')` from `utils.ts`; never write a bare `href="/..."`. Links inside Markdown content must be relative (`../../team/`).
- **Config, not code, for chapter facts:** five small JSON files in `src/config/`, one dashboard page each: `chapter.json` (names, university, IEEE section/region, founded), `contact.json` (email, socials, address, map), `numbers.json` (home stats, exposed as `site.stats`), `history.json` (About-page milestones, `site.history`), `website.json` (search description, time zone, `formspreeId`). `src/config/site.ts` merges them into `site` (keys unchanged, plus logo paths and nav); `src/config/societies.ts` holds the societies and their texts. Remaining placeholder: `TODO_FORMSPREE_ID`.
- **Dashboard:** Sveltia CMS 0.248.1 at `/admin/` (`public/admin/index.html` loads it from unpkg at that pinned version; `public/admin/config.yml`; `logo.svg` beside it). Collections (events, news, team) come first, then the five config files as `singletons`; the preview pane is off; labels and hints are written for officers. Its fields mirror `src/content.config.ts` and the config JSON files: change a schema, enum or key and update `config.yml` too. Check an option exists in the pinned version before using it (the online docs describe the latest release; `default_sort`, `{{today}}` and `backend.commit_messages` are not in 0.248.1). `output.omit_empty_optional_fields` drops empty optional fields, so code must tolerate missing optional keys (see `mapEmbedUrl` in `site.ts`). `backend.repo` is `Omar4070/ieee-smu` (the site is published from there by GitHub Pages); locally it also works via "Work with local repository" (Chrome/Edge, `npm run dev` → `/admin/index.html`).
- **Layout:** `BaseLayout.astro` (SEO/OG meta, pre-paint theme script setting `html[data-theme]`, font preload, reveal script) → `Header` / page / `Footer`. Inner pages start with `PageHeader` (props `field`, `size: 'lg'|'md'`, optional `image`): with an image the picture fills the right half of the band edge to edge (on phones it sits on top, full width); event/news detail pages pass their cover, so don't repeat the cover lower down. The footer's Join tile hides itself on pages that end with `CtaInverted` (`body:has(.cta)`). Home sections live in `src/components/home/`.
- **Event extras:** `src/pages/events/[slug].ics.ts` generates an all-day calendar file per event; the past-events "index with preview" on `events/index.astro` is CSS-only (`:has()`), no JS.
- **Contact form:** posts to Formspree; the inline script progressively enhances it and shows a fallback message while `formspreeId` still starts with `TODO`.
- **Found photos** in `src/assets/found/` are open-licence Wikimedia Commons images; their credits are in `src/data/image-credits.json` and rendered on `/credits/`. Adding or removing a found photo means updating that JSON.

## Styling gotchas

- Design tokens are CSS variables in `src/styles/global.css` (`:root` and `:root[data-theme='dark']`), exposed to Tailwind via `@theme inline` (`bg-canvas`, `text-ink`, `text-ink-muted`…). Field classes `.field-black/.field-blue/.field-ias/.field-ies/.field-pes/.field-ink/.field-surface` set background and their own text colour; they are identical in both themes. Add the class `field` too when focus rings should follow the field's text colour.
- **Astro scoped `<style>` is unlayered, Tailwind utilities are layered, so scoped CSS always wins.** Don't combine a responsive Tailwind display utility (`hidden`, `md:…`) with a scoped rule that sets the same property on the same element; put the breakpoint in the scoped CSS instead.
- **Tailwind's dev scanner can miss classes in newly created files** (e.g. `md:col-span-6` silently absent). If a new page's layout looks wrong in `npm run dev`, restart the dev server before debugging; `npm run build` is unaffected.
- **Entrance motion:** add `data-reveal` (optional `style="--i: n"` for stagger). The attribute goes `""` → `"in"` → `"done"`, and the CSS only applies while not `done`, so components can keep their own `transform` hover effects. Containers with `data-reveal-children` (Markdown bodies) get each child tagged at runtime. Hero folders use a CSS keyframe with `animation-fill-mode: backwards` instead, for the same reason. Everything is visible without JS and under `prefers-reduced-motion`.
- **Headings rise word by word** (`TextMotion.astro`, a port of React Bits SplitText): every `h1`/`h2` with `data-reveal` whose content is plain text is split into `.split-word > .split-inner` at runtime and plays a CSS keyframe when the reveal script sets `in`. A heading with child elements is left alone. `TextMotion` must render before the page and the reveal script (it does, at the top of `<body>` in BaseLayout). The same file has ScrollReveal: `data-scroll-reveal` on a plain-text paragraph (instead of `data-reveal`) makes its words sharpen with the scroll; only use it where the page can still scroll the paragraph a third of the way up.
- **Scroll timelines need their own rule.** Never write `animation-timeline` in the same rule as the `animation` shorthand: the production CSS minifier folds them into one shorthand, which Chrome rejects, so the effect silently disappears from `npm run build` while still working in `npm run dev`. Put the timeline and range in a separate, more specific rule (see `.photo-reveal` in `global.css`). `<main>` has `overflow-x: clip` because `photo-reveal` starts at 114% scale and would otherwise widen phone pages; clip, not hidden, so sticky still works.
- **Lenis** (`SmoothScroll.astro`, every page, not under reduced motion) smooths wheel scrolling only; the page still scrolls natively, so ScrollTrigger, sticky and scroll-driven CSS need no wiring. A scrollable element inside the page needs `data-lenis-prevent` (the mobile menu has it); setting `overflow: hidden` on `<html>` pauses Lenis by itself (`autoToggle`).
- **React Bits ports** (`TextMotion`, `Magnet`, `VariableProximity`): rebuilt as Astro components, no React. Their licence (MIT + Commons Clause) is in `LICENSES/react-bits.md` and must stay with the code. `data-magnet` makes a button lean towards the mouse (moves with the `translate` property, not `transform`); `CtaInverted wired` drops it on the home page, where the wire ends at the button. `data-proximity` on the closing title swells letters near the pointer; it builds on the split words, freezes the line breaks and puts an `sr-only` copy beside an `aria-hidden` visual.

## Society logos and motion

- No phasor wheel or other rotating dial in the hero (owner rejected it as ugly).
- **Never print the acronyms IAS, IES or PES as visible text** (chapter owner's rule). Use `<SocietyLogo society="IAS" height={40} variant="auto|field|white" />` for labels, and full society names in sentences. Content data keeps the acronyms as values (`societies: [IAS]`, `"society": "IES"`); components turn them into logos.
- The Team page board (`src/components/team/Board.astro`) is a single-line diagram: `lead: true` members on top, a trunk and busbar, a feeder per officer. Current is three dashed SVG lines (one per society colour) offset by a third of the dash pattern and animated with `stroke-dashoffset`; no CSS gradients. Members without `photo` get a coloured standby panel; `name` is optional in the schema. It powers up once on scroll ("breakers closing", GSAP in `Board.astro`): an inline script right after the markup adds `.is-off` before first paint, with a 4s fallback if the module has not added `.is-wired`; stages wait until 60% of the leads or of each officer row is on screen and the previous stage has finished; breakers close from the trunk outward; only portraits dim, never names. When it ends, `.is-off` and all inline styles are removed, leaving the plain live board, which is also what reduced motion and no-script visitors get. The footer also has a scoped `.board` class, so select with `.board.is-off`.
- A fixed `BackgroundWaves` layer (z-index -1) sits behind every page: sections on the plain canvas must stay transparent (don't add `bg-canvas` to them, or the waves disappear) and `.field-surface` is a translucent tint for the same reason; the owner dislikes static wave lines, so every wave must move; give a section a solid background only on purpose (the home hero does).
- Hero extras: a rolling word (`.roll-track`, each word box taller than the window so underlines never peek). Wave lines arrive with one `clip-path` sweep on the whole `<svg>` (hero and opening), never `stroke-dasharray`/`pathLength`: on a stretched viewBox with non-scaling strokes the dash is measured wrongly, so lines stop short of the edge and then snap into place.
- Header `.meter`: three scroll-progress lines (scroll timeline). `[data-tilt]` elements lean towards the pointer (BaseLayout script; mouse + motion allowed only).
- Showpiece motion: `PowerOn.astro` opening (home page only, first visit of a session, about 1.6s; navy stage with the logo alone and the three phases below it, never across it, then the stage and three colour sheets lift in the same direction: no flash, no opacity blends over the sheets; rendered only when `isHome`, and the BaseLayout head script adds `html.intro` and sets `sessionStorage.powered`; pointer-events none, any input skips it), hero "resonance" script in `Hero.astro` (with a mouse it takes over the CSS flow and redraws the paths each frame, swelling around the pointer), and click-surge rings (BaseLayout script, `.surge`). All skipped under reduced motion.
- On the home societies tiles the logo/title header sits ABOVE each photo (owner's request).
- `home/PowerStory.astro` (GSAP, home only, between the about text and the societies): scroll is the control knob on one held screen. A drive ramps a motor (V/f), an inverter chops the wave into real sine-triangle PWM, the supply splits into three phases; `src/lib/waveforms.ts` draws all of them, and the readouts show the real value of the wave on screen, so keep the two in step. Fields rise with a flowing sine edge; words leave before the edge arrives and return after it, so it never cuts text. Uses `position: sticky`, not a GSAP pin. Reduced motion, no script or windows under 520px tall get three still bands. The next heading, "Three phases, one current", is its punchline: keep them adjacent. The inspector reports two false alarms on it: few-pictures (photos below it have not lazy-loaded yet) and pinned-over-picture (hidden logos of the other beats).
- **Wave page change** (`WaveChange.astro`, every page, replaces the old cross-document view transitions): a click on a link to another page of the site adds `html.wave-out` (three colour sheets with wave crests rise, CSS transforms only), sets `sessionStorage.wave` and navigates after 500 ms; the next page's head script turns that into `html.wave-in` before first paint and the sheets lift with pure CSS, so arrival can never get stuck. Skipped for reduced motion, modifier keys, `target`/`download`, other origins, same-page links and file paths (`.ics`, images). `pageshow` (persisted) clears a page restored by Back. Arriving through it also marks the session `powered`, so the home opening never plays on top. It prefetches the page on hover.
- **Magnet field** (`MagnetField.astro`, inside `CtaInverted`, so on every page with the closing band): a canvas of needles following a real dipole field around the pointer, drifting by itself; clear space around the band's text is measured with offsets (the text may be mid-entrance). One still frame under reduced motion.
- **Event trace** (`events/EventTrace.astro`, top of the Events page): built from the events collection (last 12, date order), one pulse per event in its first society's colour; the bright layer is revealed with `clip-path` up to `--x`; each stretch is a real link (keyboard and screen-reader names); without script the whole trace is lit. No GSAP.
- **The wire** (`home/Wire.astro`, GSAP ticker): `.wire-host` in `index.astro` wraps the sections after the power story and must not get a z-index; the SVG sits at `z-index: -1` so it runs behind opaque bands and never covers content. It is measured from the page (margins, section bottoms, button) and re-measured whenever the body changes height; on screens under 900px it is one line down the left margin. The last stretch is an SVG inside `.cta` that ends at the Join button, which shows `.wire-wait` (dimmed, still usable) until the wire arrives.
- GSAP (`gsap`, with `gsap/ScrollTrigger` free to use) is installed. Import it inside an Astro `<script>` so only pages using it load it (about 44 KB gzipped with ScrollTrigger), and put every animation inside `gsap.matchMedia()` with `(prefers-reduced-motion: no-preference)`; content must stay visible without JS. Prefer CSS for simple entrances.
- Motion layer: `photo-reveal` class (scroll-timeline curtain reveal, uses the `scale` property so `transform` hovers still work), `Filmstrip.astro`, hero wave sweep, count-up script in `Stats.astro`. All scroll-driven effects sit inside `@supports (animation-timeline: view())` and `prefers-reduced-motion: no-preference`. Check motion with `scripts/motion-frames.js` (the regular screenshot script disables motion). The hero logo is also limited by window height (`118svh`) so a laptop's first screen still holds the sentence and the whole wave.

## Design rules (enforced by the taste-skill lint/inspector)

Read `DESIGN.md` before visual work; `docs/design-critique.md` records the art direction ("colour chapters": each society is a colour field, always in power-chain order). Rules the inspector fails on and that are easy to break:

- One typeface (Montserrat Variable, self-hosted via `@fontsource-variable/montserrat`; it is wide, so watch the two-line heading rule), one accent (`--primary` IEEE blue) for buttons/links. Keep to the existing type steps (`t-display-lg`, `t-headline`, `t-statement`, `t-title`, body, `t-small`), about five sizes per page.
- No eyebrows/small labels directly above a heading (put category/date/society tags *after* the title), no gradients, no shadows on resting elements, no hairline dividers or 1px outlined boxes (form fields excepted), no monospace, no icon-topped rows of identical cards.
- Every heading ≤ 2 lines at 1440/768/390 px; statements set large stay ≤ 30px.
- Corners are softly rounded (owner's choice, overrides the taste skill's square rule): `var(--radius)` 16px for cards/tiles/frames/panels, `var(--radius-sm)` 10px for buttons/inputs/photos; full-bleed bands and folder tabs stay square.
- Sentence case for headings and buttons (deliberate deviation from the web-design-guidelines' Title Case rule).
- **Dark mode is never black** (owner's rule): canvas `#0f1c2e`, surfaces `#172a42`/`#203752`, and `--black` is overridden to navy `#1c3557` so every `.field-black` block turns navy. Don't hard-code `#000` backgrounds.
- The header is SMU blue (`.field-blue`) with coloured menu tabs (`--tab`, `--tab-ink`, `--tab-line` per `li:nth-child(3n+k)` in `Header.astro`); the Join button there is white (`.header-join`).
- Colours come from the chapter palette (`assets/brand/palette.png`): IAS green `#0a792d` (white text), IES orange `#ed5703` (black text: white fails contrast), PES blue `#093f7a`, black, SMU blue `#00629b` (= `--primary`). Societies always appear in logo order IAS, IES, PES (`src/config/societies.ts` order drives the hero folders, waveform and lists).
- Thin lines on dark grounds (hero waveform in dark mode, favicon) use lighter tints (`#2fae55`, `#ff7a2f`, `#5b8fd6`); fills always use true palette colours.
- The home hero waveform (`src/components/home/Hero.astro`) is pre-computed SVG paths animated with CSS; folder hover/focus highlights a phase via `.hero:has(.folder.field-xxx:hover)`. Society logos for the hero tabs are cut from the chapter logo (`public/logos/{ias,ies,pes}-{white,black}.webp`). Logos: `site.logoColour` / `site.logoWhite` (WebP; the colour logo is the home page h1, with sr-only heading text because the image swaps per theme); regenerate icons with `node scripts/generate-icons.mjs`.
- Found photos show the societies' world and must never be presented as the chapter's own people or events.

## Board app (`board/`)

A separate Vite + React 19 + TypeScript app (own `package.json`, excluded from the site's `tsconfig.json`), built by the deploy workflow into `dist/board/` (`BOARD_OUT_DIR=../dist/board npm run build` in `board/`) and served at `<site>/board/`. Read `board/README.md` first.

- **Minimal on purpose (owner's request):** five screens only, This week, Tasks, Events, Meetings, Team. The owner asked for "just the important things to manage the team, as easy as possible", so the action plan's extras were cut (event pipeline and runway, website sync, excuse requests, reports, usage numbers, problem reports, help page, calendar files). Don't add them back unasked; a new feature must fit an existing screen.
- **Data:** Supabase (Postgres + auth + storage, free tier). `board/supabase/schema.sql` is the source of truth: six tables (members, invites, events, tasks, meetings, attendance), RLS with two levels only (`is_board()` edits everything, `is_admin()` also manages members and invites), the sign-up trigger that only lets in emails on `members` with a matching `invites` code, `reset_member_login()`, the private `pvs` bucket. Keep `src/lib/types.ts` and `src/lib/demo-data.ts` in step with it.
- **Two backends, one interface** (`src/lib/types.ts` → `Backend`): `supabase-backend.ts` when `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` are set at build time (repo variables `SUPABASE_URL`/`SUPABASE_ANON_KEY` in CI), otherwise `demo-backend.ts` (localStorage key `board-demo-data-v2` + IndexedDB, it starts with only the committee from `src/content/team/2026-2027.json` and their roles, no sample tasks, events, meetings or emails (owner's request); `?as=m-3` opens the demo as that person; update `demo-data.ts` when the committee changes). No email is ever sent: logins use invite codes.
- **Live setup:** Supabase project `ieee-smu-board` (ref `zygaxibmbtmiagircdlb`, eu-central-1), schema applied, email confirmation off, password minimum 8, site URL `https://omar4070.github.io/ieee-smu/board/`. Its URL and publishable key are workflow-level `env` defaults in `deploy.yml` (repo variables override them); the same values sit in the git-ignored `board/.env` for local builds, which makes `npm run build` in `board/` produce the live app, not the demo. The site is published from `Omar4070/ieee-smu` (GitHub Pages, Actions source). Access rules and the sign-up/reset functions were tested live with throwaway accounts.
- **Store actions** go through `attempt()` in `store.tsx`, which returns `undefined` on failure, so a void backend call must be wrapped to return `true` (otherwise success looks like failure: this broke delete, attendance and reset once).
- **Routing:** own tiny hash router (`src/lib/router.ts`), no React Router; asset paths are relative (`base: './'`), so the same build runs at `<site>/board/` or at the root of any static host (Netlify Drop is the documented no-GitHub route).
- **Installable (PWA):** `public/manifest.webmanifest` ("IEEE Board", standalone), `public/sw.js` (network first, same-origin GETs only, never Supabase; registered only in production builds), icons drawn on navy by `board/scripts/icons.mjs` (run from the repo root, uses the website's `sharp`). `src/lib/install.ts` must stay the first import in `main.tsx` so `beforeinstallprompt` is caught; `components/Install.tsx` gives the menu item and the phone-only hint on This week (iPhone gets written steps).
- **Rules (`src/lib/rules.ts`):** a task is late when undone after its due date; an event still "planning" within `ANNOUNCE_BEFORE = 4` days is flagged; past events read "Held" or "Cancelled" (no "done" status to maintain).
- **Design:** the taste skill's app-screen rules with the brand kept: no sidebar, a top bar over one centred 1040px column, every block full width (so rows are never ragged); on phones the five screens move to a bottom bar. Blue-grey ground `#f2f4f7`, white panels, near-black primary button, red only on what is late, pale tints for statuses. Dark mode is the chapter navy (owner's rule). Task lists put the one-line add form at the top. Societies never appear as acronyms (there are none in the app).
- **Checks:** `npx tsc --noEmit`; `node .claude/skills/design-taste-frontend/scripts/lint.mjs --app board/src`; `inspect.mjs --app "http://localhost:4322/board/?as=m-6#/"`; `board/tests/flows.js` and `board/tests/a11y.js` with playwright-cli (see `board/README.md`). npm's registry may be unreachable from this network: `npm install --registry=https://registry.yarnpkg.com` works, then rewrite the lockfile's `resolved` hosts back to `registry.npmjs.org`.
